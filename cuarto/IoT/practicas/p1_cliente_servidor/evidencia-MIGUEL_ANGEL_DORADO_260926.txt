# Cambio N3. Tamaño de mensaje

## Para tamaño inferior a buffer:

server: client connected from 127.0.0.1:53904
server: received 1000 bytes
server: client disconnected

## Para tamaño superior a buffer (p.ej. 10000):

server: client connected from 127.0.0.1:40196
server: received 1024 bytes
server: client disconnected

## Observaciones
Cuando el tamaño de mensaje es mayor al buffer de lectura, el mensaje se corta ya que solo se hace 
una lectura por conexión.

Para solucionarlo, meter la lectura en un bucle y controlar la cantidad de bytes recibidos cada vez.

El tiempo no crece proporcionalmente al tamaño de mensaje.

Todas las peticiones, independientemente del tamaño, tienen un tiempo "fijo" que no depende de los 
datos enviados. Apertura de conexión, llamadas al sistema, etc...

Con valores bajos el tiempo es similar. He probado tambien con 1M de bytes y el tiempo medio es
similar a 100000. Parece que gran parte del tiempo es por conexión o retardos del buffer más que
por la cantidad de datos enviados.

# STAGE 3.

## Parar servidor
Como los tiempos son muy cortos, he añadido temporalmente un sleep antes de hacer los writes al cliente.

SERVIDOR:
server: listening on port 9000
server: client connected from 127.0.0.1:37068
server: received 1024 bytes
^C

CLIENTE:
read: Connection reset by peer

Al cerrar el servidor con ctrl+c, el proceso se termina y se cierra el socket. El cliente recibe un
reset por lo que read() devuelve -1 entrando en la rama: 

if (n < 0) {
   perror("read");
   return 1;
}

El error aparece de inmediato.

## Conectar cliente a servidor no existente
CLIENTE:
connect: Connection refused

El cliente no encuentra ningún socket en ese puerto al que conectarse y devuelve un error de forma inmediata.

## Conectar dos clientes al servidor
El servidor no maneja los clientes de forma asíncrona. Debe cerrar la conexión con uno
para atender al otro.

Dejo un sleep temporal de 2 segundos para poder lanzar ambos cliente antes de que el primero termine 
exitosamente.

Arranco el servidor, el primer cliente se conecta y empieza a intercambiar mensajes. El segundo cliente se 
conecta y se queda esperando a que el servidor vuelva a llamar a accept().

Cuando termina la primera conexión, el servidor llama a acepta la conexión pendiente y comienza el 
intercambio.
